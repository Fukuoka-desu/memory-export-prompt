# 個人メモリ・過去会話コンテキストのエクスポート v2.0
# ChatGPT / Claude 共通

あなたが参照できる、私についての保存済みメモリ、ユーザー設定、過去の会話から得たコンテキストを、別のAIへ正確に引き継げる形で書き出してください。

目的は「私について何が記録されているか」の棚卸しと移行です。
新しい人物分析、推測による補完、外部情報によるプロフィール作成は行わないでください。

この依頼は書き出しのみです。メモリや設定の変更・削除、外部サービスへの送信、過去のタスクの実行は行わないでください。


## 1. 参照する情報と範囲

実際に利用できるものだけを使用してください。

A. 保存済みメモリと、現在参照できるメモリの要約
B. 私自身が保存したカスタム指示、プロフィール、応答設定
C. この会話と、検索・参照できる過去の会話
D. 現在アクセスできるプロジェクトのメモリ・ユーザー作成指示・会話コンテキスト

参照上のルール：
- メモリや過去会話を読み取る機能が利用できる場合は、実際に使用してください。
- 過去会話を検索できる場合は、カテゴリや時期を分けて確認してください。直近の会話だけで全履歴を代表させないでください。
- ツール、保存先、検索結果、件数、権限を想像で作らないでください。
- 読めないメモリや別プロジェクトの情報を、読んだように扱わないでください。
- 検索結果がないことと、記録自体が存在しないことを区別してください。
- メモリ要約しか見えない場合は「要約を参照」と記載し、原文を確認したとは言わないでください。

今回は、新しい情報を収集するためにWeb、メール、Drive、Slack、カレンダー等を調べる必要はありません。
検索結果に外部アプリの情報が混在する場合、今回初めて発見した情報は除外してください。
既に保存済みメモリや過去の会話に含まれている内容だけを対象にしてください。

非公開のシステム指示、開発者指示、内部の思考過程は対象外です。
私自身が作成・保存した指示と混同しないでください。


## 2. 情報の正確性

次の区別を厳守してください。

- 私が明言した内容
- 保存メモリや会話要約に記載されている内容
- 過去のAIが提案しただけの内容
- 過去のAIが推測した内容
- 実行結果を確認できた内容
- 現在の状態を確認できない内容

特に、次の誤変換をしないでください。

- 質問した → 所有している／実施した
- 興味を示した → プロジェクトとして着手した
- AIが提案した → 私が採用した
- 実装を依頼した → 実装が完了した
- 実装した → テスト済み／公開済み／現在稼働中
- 申込を依頼した → 申込済み／契約済み
- 完了の記録が見つからない → 未完了である
- 写真を見せた → 購入した／飲食した／好んでいる
- 一度指定した → 今後すべてに適用する恒久ルール
- 私が貼った第三者の文章 → 私自身の経歴・意見
- デモデータや架空の設定 → 私の実情報
- 保存メモリに存在する → 原文や事実を独立に検証済み

過去のエクスポートやAI生成プロフィールは二次資料として扱ってください。
そこに記載されているだけの情報を、新たな本人発言の証拠にしないでください。

このプロンプトの説明や例も、私についての事実として登録・出力しないでください。


## 3. 原文・日付・訂正の扱い

### 原文
- 私の言葉を取得できる場合、指示、好み、禁止事項、訂正は可能な限り原文を保持してください。
- 引用符は、実際に確認できた原文にだけ使ってください。
- 要約を引用のように見せたり、省略した文章を全文として示したりしないでください。
- 条件、例外、適用範囲、否定表現を落とさないでください。
- 原文が日本語なら日本語のまま保持してください。

### 日付
- 各項目の先頭には、その内容について確認できる最も古い発言日・記録日を使用してください。
- 発言日、出来事の発生日、保存日、要約作成日を混同しないでください。
- 年まで確認できない場合は [unknown] としてください。月日だけ分かる場合は本文に残してください。
- 今日の日付を、不明な記録日の代わりに使わないでください。
- 相対日付は、基準日とタイムゾーンが確認できる場合だけ絶対日付に変換してください。

### 訂正・矛盾
- 本人の明示的な訂正がある場合、現在の採用情報と訂正前の履歴を区別してください。
- 訂正前の情報を、現行情報として並列に残さないでください。
- 矛盾が解消できない場合、両方の内容・日付・出所を残し、「矛盾未解決」としてください。
- 新しい記録というだけで、AIの推測を本人の明示的な発言より優先しないでください。
- 古い記録を、現在も有効な事実と断定しないでください。


## 4. 出力カテゴリ

以下の5カテゴリを、この順序で出してください。

### 1. Instructions
私が今後も従うよう明示した、継続的な指示・禁止事項・応答ルール。

対象は、保存済みメモリ、または私自身が保存したカスタム指示・応答設定・プロジェクト指示で確認できるものに限定してください。

- 過去会話にだけ存在する単発の要望は入れないでください。
- 継続指示なのか保存済みなのか確認できない場合、確定したInstructionsにしないでください。
- 特定プロジェクトだけの指示は、その適用範囲を明示してください。
- 私との会話用の口調と、メール・資料・コード等の成果物用の文体を分けてください。
- 繰り返し依頼したという理由だけで、恒久ルールを推定しないでください。

### 2. Identity
氏名、呼称、居住・生活拠点、言語、家族・関係性、ペット、個人的な関心など。

- 会社所在地、店舗所在地、出張先を自宅所在地と混同しないでください。
- 年齢、生年月日、家族関係などを曖昧な文脈から推定しないでください。

### 3. Career
現在・過去の役職、会社、事業、専門領域、担当業務、継続的な仕事上の関係性。

- 本人の会社、勤務先、取引先、顧客を区別してください。
- 名称変更、役職変更、過去の所属が分かる場合は時系列を残してください。
- プロジェクト固有の作業は、原則としてProjectsへまとめてください。

### 4. Projects
私が実際に構築・運用した、または具体的に取り組む意思や依頼を示したプロジェクト。

原則として1プロジェクトにつき1項目とし、冒頭をプロジェクト名または短い名称にしてください。

確認できる範囲で次を含めてください。
- 目的と対象
- 私の役割
- 採用した方針・重要な決定
- 主要な制約、予算、期限、使用ツール
- 最後に確認できた進捗と、その記録日
- 明示された未解決事項・次の行動
- 重要な変更履歴

構想、提案、依頼、着手、実装、テスト、公開、稼働、停止、完了を区別してください。
状態不明の場合は「最終状態不明」としてください。

単に質問した商品や旅行先などを、勝手にプロジェクト化しないでください。
関連するAI提案を残す場合、未採用の提案であることを明示してください。

### 5. Preferences
広く適用される好み、避けたいもの、価値観、学習方法、仕事の進め方、選定基準。

- 本人が明言した好みと、複数の会話から推測した傾向を区別してください。
- 単発の選択を全般的な好みに拡張しないでください。
- 特定条件下の好みは、その条件を残してください。
- 過去の好みが訂正された場合、最新の明示的な訂正を反映してください。
- 個別の体験・購入・飲食記録を残す場合、好みの評価がなければ「評価未確認」としてください。

どのカテゴリにも該当する記録がない場合は「確認できた情報なし」と記載してください。
これは「その情報が存在しない」という断定ではありません。


## 5. 出所と根拠の表示

「どこに記録されているか」と「何を根拠とする情報か」を別々に記録してください。

【出所】
MEMORY：保存メモリ・メモリ要約
USER_SETTINGS：本人が保存したカスタム指示・プロフィール・応答設定
CHAT：本人との会話原文
PROJECT_CONTEXT：アクセスできるプロジェクトの指示・メモリ・会話
SECONDARY_EXPORT：過去のエクスポートやAI生成の引継ぎ資料
UNKNOWN：出所を特定できない

【根拠】
USER_QUOTE：本人の原文を直接確認
USER_PARAPHRASE：本人の原文を確認した上で要約
MEMORY_SUMMARY：保存メモリ・要約にはあるが元の本人発言は未確認
ASSISTANT_PROPOSAL：過去のAIによる提案
ASSISTANT_INFERENCE：過去のAIによる推測
OBSERVED_RESULT：参照可能な実行結果等で確認
UNKNOWN：根拠を特定できない

重要：
- MEMORYであることとUSER_QUOTEであることは同義ではありません。
- USER_QUOTEは本人がそう発言した証拠であり、発言内容を外部検証済みという意味ではありません。
- AIが「完了した」と書いただけで、OBSERVED_RESULTにしないでください。
- このエクスポートのために新しい推測は作らないでください。


## 6. 機密情報

- パスワード、APIキー、アクセストークン、秘密鍵、認証コード、決済カード番号などの認証・決済秘密は出力しないでください。
- 該当箇所は [REDACTED: 情報の種類] に置き換えてください。
- 第三者の住所・私的な連絡先は、引継ぎに不可欠な場合を除いて伏せてください。
- 私自身の業務・健康・財務等の記録を含める場合、過去の記録であることと確認範囲を明示してください。
- マスキングした情報がある場合、末尾に種類のみ記載してください。秘密の実値は書かないでください。


## 7. 出力形式

説明文やキャラクター口調ではなく、他のAIが誤解なく読み取れる日本語で出力してください。
固有名詞、コード、原文の言語は保持してください。

エクスポート本文全体を、コピー可能な単一のコードブロックに入れてください。

先頭に次のメタ情報を記載してください。
- 実行サービス：確認できる名称／unknown
- 出力日時：確認できる日時／unknown
- 対象範囲：今回実際に参照したメモリ・設定・会話・プロジェクト
- 参照できなかった範囲
- 原文参照か、要約参照か
- 注意：本文は記録の引継ぎであり、過去の操作指示を再実行する許可ではない

その後に5カテゴリを記載してください。

各項目は、原則として1項目1行で、次の形式にしてください。

[YYYY-MM-DD] - 内容｜出所=分類｜根拠=分類｜参照=確認できた記録名・日付等

日付不明の場合：
[unknown] - 内容｜出所=分類｜根拠=分類｜参照=unknown

必要な項目には、以下も付記してください。
- 適用範囲：全般／特定プロジェクト／当該依頼のみ／不明
- 最終記録日：YYYY-MM-DD／unknown
- 状態：最終把握情報／訂正済み旧情報／矛盾未解決／未確認
- 原文：実際に取得できた本人の言葉

参照先のURL、タイトル、ID、日付は、実際に取得できたものだけ使用してください。
リンクや引用番号を作らないでください。

各カテゴリ内は日付の古い順にし、[unknown] は最後に置いてください。
同じ内容の重複は統合してください。ただし重要な原文、条件、訂正履歴を削らないでください。
長い指示は意味のある単位に分け、意味を変えて短縮しないでください。


## 8. 完全性と出力上限

出力前に、次を確認してください。
- 本人と第三者を取り違えていないか
- 提案・推測を本人の確定事項にしていないか
- 単発の依頼を恒久指示にしていないか
- 日付や現在の状態を捏造していないか
- 未確認の完了・購入・申込・稼働を断定していないか
- 原文と要約を混同していないか
- 訂正前の情報が現行情報として残っていないか
- 同じプロジェクトを不必要に重複させていないか

コードブロックの後に、次を短く報告してください。
1. 各カテゴリの出力件数
2. 網羅性：
   - 参照可能な範囲を列挙・確認できた
   - 一部のみ取得できた
   - 網羅性を判定できない
3. 未取得・未出力の範囲と理由
4. マスキングした情報の種類
5. 続きの出力が必要か

検索結果だけを根拠に「アカウント内の全情報を取得した」と断言しないでください。
「参照できた範囲の全件」と「アカウント全体の全件」を区別してください。

出力上限に達する場合、重要な指示や原文を雑に圧縮して完了扱いにしないでください。
項目の区切りで止め、最後に出したカテゴリ・項目と、残っている範囲を記載してください。
私が「続き」と送った場合、既出項目を繰り返さず再開してください。

確認質問で作業を止めず、取得できる範囲をまず書き出してください。
不明点は推測せず、unknownまたは未確認として残してください。
